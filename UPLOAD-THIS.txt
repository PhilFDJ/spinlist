WEBSITE FIRST, THEN THE APP
---------------------------
Gig Window 1.4.0 calls two endpoints that only exist once server.js and
lib/db.js are live. Deploy this first, or the app's Serato panel will show
"none" for the do-not-play list and the Test button will do nothing —
which looks like a broken app when it isn't.


WHAT'S IN HERE
==============

BUGS FIXED
----------
Contract and questionnaire templates invisible. lib/db.js defined
listTemplates and deleteTemplate TWICE in one object literal, so the
wedding planner's versions silently overwrote the CRM's. Every CRM template
was being written to one place and read from another.

Clients never recorded. createClient was called from exactly one place —
the "new client" button. Enquiries produced bookings with contact details
attached but nobody in the Clients list.

Custom field answers invisible. The booking screen never displayed them at
all, so anything a client answered vanished on arrival.

isrc wiped on every song edit. setWeddingBlockSongs rebuilt each song from
a fixed field list that omitted isrc, so it only survived until the next
change. Matters for Serato matching and the now-playing feature.

Live requests died at the couple's lock date. The button that opens guest
requests was gated on the couple's EDIT lock, so setting a lock two weeks
out removed the control before the gig. Also: an assigned sub-DJ could
never open requests at all, on the page or through the API.

Checkboxes 261px wide. One blanket CSS rule sized every input to 100%
width with 11px padding, checkboxes included, pushing labels off the row.
Affected "Use this one by default", which predates all of this.

Quote modals see-through and unscrollable. My mistake — I used a CSS class
that doesn't exist in your stylesheet.

NEW
---
Enquiry forms, fully customisable. A form is one ordered list you control:
rename, reorder, hide or require any question including the standard ones,
set your own event-type options, add your own questions (short answer, long
answer, choose one, yes/no, date, TIME, ADDRESS with map lookup), and
section headings. Each questionnaire is its own embeddable form with its
own token and iframe snippet, so a multi-brand DJ can put a different form
on each website with everything landing in one pipeline.

Custom fields are internal by default and only public when you say so —
enforced on the form AND on submission, so nothing internal can be set by
a crafted request. Check fee_to_dj before putting a form on a live site.

Quote builder. Packages or blank lines, quantities, prices, descriptions,
pictures, deposit as a percentage or fixed amount, balance due N days
before with the real date shown. Sent quotes lock, matching the server.

Quotes carry a contract. Pick the agreement on the quote; it's raised
automatically when they accept, with that quote's figures merged in, and
they're sent straight to sign. Decline it and no agreement exists.

The client-facing pages that never existed: quote.html and contract.html.
View, accept, decline, sign, pay the deposit. Both print properly.

Song notes. Couple and DJ each get their own per song, shown on screen and
on the PDF run sheet, attributed. They lock on the song deadline.

Request blocks and do-not-play blocks are now FLAGS, not block names. The
old checks matched the literal names "Play If Possible" and "Do Not Play",
so renaming a block silently broke live requests or made a ban invisible.
Request blocks save with music templates.

Now-playing API for the Gig Window app, plus the red do-not-play alarm in
the gig window itself.

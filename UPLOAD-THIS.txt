WHY THE TEST DIDN'T FLASH
-------------------------
Two faults, both mine, both on the website side.

1. NO NAME FALLBACK FOR DO-NOT-PLAY BLOCKS

   For live requests I kept a fallback so a block still named "Play If
   Possible" carries on working. For do-not-play I forgot to.

   Every wedding in your diary was created before the flag existed, so its
   "Do Not Play" block has no flag on it. The ban list came back EMPTY for
   every existing gig. Only a brand-new wedding built from the default
   template would have worked — which is exactly the one case I tested.

   A block is now treated as do-not-play if it's flagged OR simply named
   that way. Tested against 20 naming variants: "Do Not Play", "do not
   play", "Do-Not-Play", "do_not_play", "Don't Play", "Dont-play", "Never
   Play", "Banned", "Banned songs" — while correctly NOT matching "Play If
   Possible", "Playlist" or "Party starters".

   Nothing needs re-saving. Your existing weddings work as they are.

2. THE FALLBACK PATTERN WAS BROKEN ANYWAY

   Found while testing the above: the regex had been written into the file
   with doubled backslashes, so it matched a literal backslash rather than
   a word boundary and could never match anything at all. Fixed, and I
   swept every other regex in all eight files for the same fault — the only
   other hit is pre-existing iCalendar escaping, which is correct as it is.
